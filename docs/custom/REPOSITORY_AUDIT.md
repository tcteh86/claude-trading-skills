# Repository audit

## Scope and evidence

Baseline commit `4080042a`. The tracked tree inventory covers 2,606 files, including 74 skill manifests (62 production, 12 beta), 74 packaged artifacts, 14 workflow YAMLs, six skillsets, 437 skill-side pytest modules, 71 skill requirements files, 11 GitHub Actions workflows, examples, launchd, and bilingual Jekyll documentation. The audit inventoried the full tree and traced representative critical paths through configuration, scripts, tests, generated outputs, and provider integrations. It is a source and development-environment review. Live provider entitlements, every calculation branch, historic Git contents, and profitability are outside the verified evidence.

## Findings and trade-offs

1. **Market scope and time.** The growth screener explicitly enumerates NASDAQ, NYSE and AMEX in `pipeline_common.py`. A current listing sample or bulk-estimate response cannot substantiate a historic or global ranking. Preserve the existing coverage classifications. Record delistings, ticker aliases, filing availability, revision lineage, eligible listings, and exclusion reasons before historical or market-wide claims.
2. **Financial assumptions.** The growth screener uses configurable preferred forward P/E and EV/FCF thresholds and estimate coverage. Thin analyst coverage can skew small-cap selection. P/E, EV/FCF, dividend yield, and peer multiples can mislead if denominators are nonpositive, cycles differ, fiscal periods/currencies mismatch, or diluted shares and special distributions are mishandled. The Kanchi payout triad and sector guidance provide a base, while SGX REITs need issuer-specific DPU and distributable income reconciliation, refinancing stress and sponsor/tenant concentration. These are model limitations and validation targets, rather than confirmed arithmetic defects.
3. **Backtest realism.** ManifoldBT exposes fixed basis-point fee/slippage and configurable fill delay. Fixed costs omit size-dependent impact and trading constraints in thin names. Same-bar fill after a close-derived signal can introduce look-ahead. Backtest Expert has eligibility gates and bias guidance, while execution- and cohort-level evidence still needs independent tests. Use actual announcement availability, delisted names, forward holdouts, and realistic fill policy. [Bias checklist](../dev/strategy-research-bias-checklist.md) · [ManifoldBT specification](../../skills/manifoldbt-backtester/references/strategy_spec.md)
4. **Claude and Codex.** WebSearch/WebFetch prompts, named Claude tools, `claude -p` envelopes, Claude session paths, launchd and Claude automation are platform-dependent. Deterministic Python and validated JSON handoffs work independently. Add opt-in Codex wrappers for a few workflows, with offline artifacts or an explicit unavailable state for tool-dependent evidence. Preserve upstream rendering/packaging conventions. [Claude instructions](../../CLAUDE.md)
5. **Security and privacy.** The detect-secrets hook and CI scan exclude Markdown, JSON, CSV and ZIP, all plausible paths for private artifacts. The canonical-path check cannot identify holdings in arbitrary file formats or paths. Query-string credentials can be exposed by unsafe logging even when the client uses HTTPS. External text can steer tool-using agents, and session mining is a distinct disclosure boundary. Restrict outbound hosts and operations, disable maintenance tools in research, use synthetic fixtures, scan staged payloads and sanitize metadata/errors. The configured Bandit scan of skill source reported zero findings within its selected checks and exclusions. Local source review identifies control gaps. Exploitability and remote deployment behavior were outside the audit. [Pre-commit configuration](../../.pre-commit-config.yaml) · [Security CI](../../.github/workflows/ci.yml) · [Privacy policy](../en/privacy.md) · [Security policy](../../SECURITY.md)
6. **Verification.** The inventory records 61 skills with financial logic marked `not_verified`, 54 with empirical validation marked `not_verified`, and 62 with provenance marked `not_verified`. Unset and inapplicable statuses are separate. These declarations measure evidence status, independent of pytest counts. Test-policy floors are 85% for four core skills, 70% for other executable skills, and 75% aggregate, with time-limited waivers. Extend with as-of, SGX, drift, finance golden cases, and E2E failure-closed tests. [Skill index](../../skills-index.yaml) · [Coverage policy](../dev/ci-test-coverage-policy.md)
7. **Licensing and dependencies.** MIT covers repository code under its terms. Market prices, classifications, exchange filings, news, ETF holdings, and derived datasets may carry separate rights. Generated clients and provider response contracts are useful for schema drift, but do not prove coverage, comparability, or permission to cache and redistribute. [Provider contracts](../dev/provider-contracts.md) · [Provider matrix](DATA_PROVIDER_MATRIX.md)
8. **Upstream merge risk.** Shared catalogs, YAML schemas, bilingual generation, CI policy, lockfiles, generated helpers, and packaged archives are collision points. Route custom workflows through independent configuration and thin adapters. Pin behavior through fixtures against the upstream baseline and rerun those checks after upstream updates. Use upstream generators for deliberate upstream-facing fixes.
9. **Workflow safety depends on the runner.** The multi-asset YAML explicitly treats its prerequisite as informational. Metadata validation alone does not enforce a prior regime decision at runtime. A fork runner must check artifact presence, freshness and scope before downstream decisions. Portfolio reconciliation and position sizing are usable primitives, with look-through and broker-neutral exposure aggregation still to design. [Multi-asset workflow](../../workflows/multi-asset-opportunity-daily.yaml) · [Portfolio scripts](../../skills/portfolio-manager/scripts)

## Validation performed

The onboarding run installed the locked dev/CI environment. Ruff lint and formatting, codespell, index and skillset validation, generated skill and workflow docs checks, and four documented offline CLI examples passed. Five isolated skills passed 1,597 tests in total and compatibility regressions passed five tests on Linux/Python 3.13. Trader-memory initially hit the read-only default uv cache, then passed after using a writable cache and disabling nested sync. These checks validate development operation and selected interfaces. They do not certify the financial validity, live-provider coverage, or license status of the proposed product.

The root pytest run reported 17,606 passed, one failed, three skipped, and 13 passing subtests. The failing theme-detector test simulates an unavailable market-calendar package. In the root run its exception escaped instead of mapping to exit code 2. The pinned dependency check and isolated theme-detector row passed, with 639 passed and one skipped because optional `finvizfinance` was absent. The behavior is consistent with cross-suite import state, although the triggering interaction remains unconfirmed. Use isolated CI rows as the regression baseline and track the root-run failure separately. Provider, API, compatibility and docs-source validators also passed.
